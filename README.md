# Amangeldy Threads Manager — первая версия
Русский язык. 2 поста ежедневно, третий опционально. Управление в личном Telegram.
Код подготовлен для одного постоянно работающего сервиса Railway с постоянным диском.
Реальные внешние запросы и публикации без ваших токенов не проверялись.

## GitHub
Распакуйте архив. Загрузите ВСЁ СОДЕРЖИМОЕ папки в корень репозитория:
main.py, Dockerfile, requirements.txt, editor.json, knowledge.md, README.md,
test_bot.py и .gitignore. Не загружайте сам ZIP и токены.

## Railway
New Project → Deploy from GitHub repo → ваш репозиторий.
Railway должен обнаружить Dockerfile. Для сервиса создайте Volume с Mount Path /data.
Оставьте одну реплику. Отключите сон/serverless. Публичный домен не нужен (Telegram polling).
Не допускайте одновременно работающих старого и нового deployments этого бота.
Запуск: python -u main.py (уже указан в Dockerfile).

Variables:
- TELEGRAM_BOT_TOKEN — токен НОВОГО бота BotFather.
- TELEGRAM_OWNER_ID — ваш числовой Telegram ID; можно получить командой /whoami старому боту отчётности.
- OPENAI_API_KEY — ключ проекта OpenAI с доступным балансом.
- OPENAI_MODEL — gpt-4.1-mini (можно изменить на доступную совместимую модель).
- THREADS_ACCESS_TOKEN — пользовательский токен Threads клиники.
- THREADS_EXPECTED_USERNAME — amangeldy.clinic (без @; измените если фактическое имя другое).
Токены — только в Variables Railway. Не в GitHub или переписку.

## Первый запуск
1. Откройте нового Telegram-бота, /start.
2. /check — проверяет, какому аккаунту принадлежит токен.
3. /search — проверяет поиск. Ноль внешних результатов не доказывает работоспособность публичного поиска.
4. /preview — пробный текст без публикации.
5. /resume — включает самостоятельную публикацию по расписанию. Это разрешает реальные публичные посты.
6. /pause — останавливает следующие публикации. Уже отправленный API запрос отменить невозможно.

По времени Астаны: поиск 08:00, 13:00, 18:00; публикации 10:00 и 15:00;
/third on добавляет 19:00 при наличии новых тем последнего поиска; /third off отключает.
Отчёт в 21:00. После простоя старые слоты не догоняются. Пропуск окна 15 минут пропускает пост.
Ошибки поиска не блокируют резервные темы. Непройденная редакторская проверка пропускает слот.
/notes — пожелания. /queue — история. /report — доступная статистика последних 6 постов.
Удаление только постов этого бота: /delete ID, затем /confirm_delete ID в течение 5 минут.

## Честные границы первой версии
- Официальный поиск по словам, без Apify. Публичный поиск может потребовать дополнительного доступа Meta.
- Свежие внешние обсуждения используются как темы, не как медицинские источники.
- Нет достоверного рейтинга «всех трендов», сбора чужих личных данных или оценки чужих охватов.
- Семь рубрик — адаптированная ротация. Пока нет медицинских фактов, чекпов/цен, реальных кейсов,
  автоответов и автоматического обучения на статистике. Отчёт по статистике есть.
- Медицинские ограничения намеренно жёсткие до отдельной настройки утверждённой базы.
  Проверка ИИ не гарантирует отсутствие ошибок. Сначала оцените тексты через /preview.
- Токен НЕ продлевается автоматически в этой версии. Следите за его сроком и заменяйте
  в Variables до истечения. Для автоматического обновления понадобится отдельная настройка
  обмена на долгоживущий токен и сохранения срока действия.
- При неоднозначном результате публикации запись помечается uncertain и бот ставится на паузу;
  автоматических повторов нет. Проверьте Threads и запись posts вручную перед возобновлением.
- SQLite хранится на Volume; удаление Volume уничтожает историю. Резервируйте диск отдельно.

## Проверки
python -m unittest -v test_bot
Тесты без внешних запросов: проверка аккаунта, пауза, отказ при повторе текста,
неоднозначная отправка, запрет повторного запуска слота и подтверждение удаления.

## Обновление: автоматические проверки
Включён GitHub Actions: каждый push и pull request запускает тесты без токенов и публикаций.
Скопируйте скрытую папку `.github` вместе с файлами. Результат: вкладка Actions → Bot checks.
Зелёный результат проверяет локальную логику; доступ Meta проверяется отдельно через /check и /search.
Автоматического исправления кода эти проверки не выполняют.

Дополнительные сотрудники: TELEGRAM_ALLOWED_IDS=123456,789012 (числовые ID через запятую).
Все указанные сотрудники имеют одинаковые права, включая включение постинга и удаление.
Автоматические уведомления получает TELEGRAM_OWNER_ID; ответы на команды — отправитель.

Исправления: повторная отправка уже обработанной записи запрещена; восстановление после
незавершённой публикации ставит бот на паузу; блокировка процесса берётся до восстановления
базы; провал поиска сбрасывает счётчик тем; источники старше 7 дней по времени сбора исключены.
Удалён случайный файл download. Токены и локальная база исключены из Git и Docker-контекста.
